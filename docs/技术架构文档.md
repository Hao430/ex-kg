## 1. 系统架构全景与技术选型透视

枝想 采用现代全栈架构（Modern Full-Stack Architecture），将**二维拓扑图谱渲染、流式大模型推演引擎、分布式多租户鉴权以及生产级双模存储底座**深度融合。

## 3. 生产级数据库完整架构 (Database Schema)

系统实现了严密的 **19 张实体关系表**（建表与自动迁移位于 `server/core/schema.ts`，与 `docs/数据库建表脚本.sql` 一致），具备自动迁移、外键级联与索引集群保障。后端采用分层架构：`routes`（校验与响应）→ `services`（业务编排）→ `repositories`（双模数据访问）→ `core`（连接池/建表/内存兜底）。

- `canvas_shares`、`canvas_snapshots`、`canvas_templates`、`tags`、`canvas_tags`、`node_attachments`、`user_api_keys`、`notifications` 共 8 张为**一期预留空壳**，二期才激活。

### 3.2 核心数据表详细字段规范

1. **`users` (核心用户表)**：
   - `id`: UUID 主键
   - `email`: VARCHAR(255) 邮箱（部分唯一索引 `WHERE deleted_at IS NULL`，注销冷却期内同邮箱可用新账号新 id 重注册）
   - `password_hash`: 加密密码散列（scrypt 版本头格式，见 §1.1）
   - `name`, `avatar`: 用户昵称与头像
   - `role`: 'user' | 'vip' | 'admin' 权限标识（体验版为 `user`）
   - `vip_expires_at`: 会员有效截止时间戳（到期进入硬锁定态，禁推理与新建画板；含 7 天宽限期语义，见 §5）
   - `is_active`: 账号启停状态
   - `failed_attempts` & `locked_until`: 防暴力破解锁机制
   - `last_login_at`: 最近登录时间
   - `email_verified`: 邮箱验证状态（未验证不可发起 AI 推理，403 `EMAIL_NOT_VERIFIED`）
   - `verify_token` & `verify_expires_at`: 邮箱验证一次性令牌（24h 有效）
   - `reset_token` & `reset_expires_at`: 找回密码一次性令牌（1h 有效）
   - `deleted_at`: 注销软删除时间戳（30 天冷却期内可由 Admin 恢复，超期硬删级联）

2. **`canvases` (画布元数据表)**：
   - `id`: VARCHAR(64) 画布唯一标识
   - `user_id`: UUID 归属用户 ID (外键级联删除)
   - `title`: 画布标题
   - `viewport_x`, `viewport_y`, `viewport_zoom`: 视口状态记忆

3. **`nodes` (节点全要素表 - 杜绝数据丢失)**：
   - `id`, `canvas_id`, `parent_id` (自关联树形层级)
   - `type`: 'chat' | 'note'
   - `title`: 节点精简标题 (用于大纲与折叠状态)
   - `question`: 核心提问
   - `answer`: AI 生成答案
   - `note`: 便签记录
   - `content`: 兼容富文本内容
   - `messages`: JSONB 结构，完整存储该节点多轮交互会话记录
   - `status`: 'idle' | 'generating' | 'error' | 'suggested'
   - `pos_x`, `pos_y`, `depth`: 空间坐标与逻辑深度
   - `model_used`: 推演所用模型
   - `grounding`: JSONB 存储联网搜索来源卡片
   - `is_collapsed`: 布尔值，卡片折叠/展开状态
   - `branch_trigger_phrase`: 划词引申分支的原词短语
   - `enable_web_search`: 是否开启联网搜索
   - `color`: 主题标注色
   - `custom_data`: JSONB 扩展预留

4. **`edges` (拓扑连线表)**：
   - `id`, `canvas_id`, `source_id`, `target_id`
   - `source_handle`, `target_handle`: React Flow 锚点对齐参数
   - `label`: 连线提示标签
   - `animated`: 是否开启动画流光效果
   - `style`: 自定义连线样式配置 JSONB
   - `type`: 'smoothstep' | 'bezier'

5. **`sessions` (会话凭证表)**：
   - `id`, `user_id`, `token`, `expires_at`, `ip_address`, `user_agent`, `device_type`：用于会话风控与多端登录管理。

6. **`orders` (会员订阅订单表)**：
   - `order_no`: 唯一商户业务单号 (ORD-TIMESTAMP-XXXX)
   - `user_id`, `plan_id`, `plan_name`, `amount_cents` (金额分), `status` ('pending'|'paid'|'failed'|'refunded'), `duration_days`, `payment_method`, `paid_at`。
   - 套餐定价：周度 Pro 会员（周卡）¥9.9 / 月度 Pro 会员（月卡）¥24.9 / 年度 Pro 会员（年卡）¥199。一期由 `MockProvider` 驱动，VIP 亦可由 Admin 直接赠送。

7. **`ai_models_config` (动态模型路由配置表)**：
   - 动态配置模型路由：`display_name`, `provider`, `context_window`, `is_vip_only`, `is_active`。

8. **`ai_request_logs` (模型性能与调用审计日志表)**：

   - 已配套自动清理任务（`server/jobs/log-cleanup.ts`，启动即跑 + 每 24h 执行）：默认保留 90 天（`AI_LOG_RETENTION_DAYS` 可配）。

> **已废弃**：算力点数体系已在一期整体移除（用户余额字段与消费流水平账表均已删除），权益改为画板数与 AI 节点数的服务端配额校验，一次推理不再产生任何扣费写操作。

### 3.3 高性能索引与数据一致性机制
- **软删除设计 (Soft Delete)**：`canvases`、`nodes`、`users` 均包含 `deleted_at TIMESTAMPTZ`，并在部分索引中添加 `WHERE deleted_at IS NULL`，支持 30 天回收站恢复机制与合规注销冷却期。
- **自动时间戳触发器**：挂载 `trigger_set_timestamp()` 保证任一表在 UPDATE 时自动同步更新 `updated_at`，无需应用层硬编码时间。
- **核心查询索引集群**：
  - `CREATE INDEX idx_canvases_user_updated ON canvases(user_id, updated_at DESC) WHERE deleted_at IS NULL;`
  - `CREATE INDEX idx_nodes_canvas_id ON nodes(canvas_id) WHERE deleted_at IS NULL;`
  - `CREATE INDEX idx_nodes_parent_id ON nodes(parent_id);`
  - `CREATE INDEX idx_edges_source_target ON edges(source_id, target_id);`
  - `CREATE INDEX idx_orders_user_created ON orders(user_id, created_at DESC);`
  - `CREATE INDEX idx_ai_logs_user ON ai_request_logs(user_id, created_at DESC);`
- **GIN 全文检索**：
  ```sql
  CREATE INDEX idx_nodes_fulltext ON nodes 
    USING GIN (to_tsvector('simple', COALESCE(title, '') || ' ' || COALESCE(question, '') || ' ' || COALESCE(answer, '') || ' ' || COALESCE(content, '') || ' ' || COALESCE(note, '')));
  ```

## 4. 关键算法与技术实现机制

### 4.1 大画布性能优化与分支剥离导出算法 (150+ Nodes Subtree Extraction)
当画布节点数量超过 150 个时，DOM 节点重绘与 SVG 连线计算开销增大。枝想 实现了自动监控与一键子树剥离机制：

```typescript
/**
 * 递归收集目标分支节点的所有子孙节点与关联连线，并导出为新画板
 */
export function extractSubtree(
  rootNodeId: string,
  nodes: Node[],
  edges: Edge[]
): { subtreeNodes: Node[]; subtreeEdges: Edge[]; remainingNodes: Node[]; remainingEdges: Edge[] } {
  const descendantIds = new Set<string>([rootNodeId]);
  let added = true;

  // 沿出边迭代汇聚所有子孙节点 ID
  while (added) {
    added = false;
    for (const edge of edges) {
      if (descendantIds.has(edge.source) && !descendantIds.has(edge.target)) {
        descendantIds.add(edge.target);
        added = true;
      }
    }
  }

  const subtreeNodes = nodes.filter(n => descendantIds.has(n.id));
  const remainingNodes = nodes.filter(n => !descendantIds.has(n.id));

  // 连线过滤：两端均属于子树的边归入新画板，其余保留或剔除
  const subtreeEdges = edges.filter(e => descendantIds.has(e.source) && descendantIds.has(e.target));
  const remainingEdges = edges.filter(e => !descendantIds.has(e.source) && !descendantIds.has(e.target));

  return { subtreeNodes, subtreeEdges, remainingNodes, remainingEdges };
}
```

### 4.2 卡片头部视觉人体工学重构 (Anti-Crowding Node Header)
在早期版本中，节点顶部堆叠了深度徽标 (Depth Tag)、模型选择器、状态标签及多种操作按钮，在节点宽度限制下导致按钮折叠与换行错位。
- **重构方案**：移除冗余的深度数字标签（深度已由 X 轴位置自然呈现，数字无直接用户价值）；
- 将功能区划分为「左侧状态与标题」与「右侧紧凑操作组」，采用单行 flex-nowrap 布局与图标提示，彻底根绝折叠错位。

### 4.3 祖先上下文链回溯组装 (Ancestry Context Assembly)
在向 AI 提出分支问题时，算法沿连线逆向回溯至根节点，生成多轮问答对话序列（Multi-turn History）：
$$Ancestors(Node) = [Root, ..., Parent, Current]$$
在请求体中自动转换为 `[{ role: 'user', content: '...' }, { role: 'model', content: '...' }]`，确保即使分支深达 10 层，AI 依然掌握上游所有的前提假定与结论。

## 5. 安全体系与企业级风控

1. **强制登录与越权防护 (IDOR Protection)**：
   不提供游客模式，未登录访问任意 `/api/canvases/*` 一律返回 401 并跳转登录页；画布操作在后端校验 `canvas.user_id === req.user.id`，任何未经授权的修改请求即刻抛出 403 异常并记录审计日志。
2. **防暴力破解与账号安全**：
   连续 5 次输入错误密码后，账号进入 15 分钟锁定期 (`locked_until`)；登录接口自身限流 15 次/分钟/IP。密码散列采用 scrypt N=2^16/r=8/p=1 版本头格式，存量哈希登录时透明升级。
3. **接口配额与流量限制**：
   `roleBasedRateLimiter` 按用户角色实施阶梯限流（**体验版 25 / VIP 60 / Admin 120 次每分钟**，按 `user_id` 或 IP 计数），防止爬虫恶意占用模型推理资源。
   滥用防线限流清单：注册 `signup` 5 次/小时/IP；找回密码 `forgot-password` 5 次/小时/IP；验证邮件重发 `resend-verification` 3 次/10 分钟/用户。
4. **权益配额服务端化**：
   画板数量、每画板 AI 节点数量、子分支导出、`is_vip_only` 模型白名单四类限制全部由后端中间件强制校验，前端不再承载 `isVip` 判断，直连 API 无法绕过。
5. **邮箱验证、注销流程与审计合规**：
   - **邮箱验证**：注册后需完成邮箱验证（24h 令牌邮件，Nodemailer 发送）方可发起 AI 推理，未验证请求返回 403 `EMAIL_NOT_VERIFIED`；验证邮件重发独立限流。
   - **找回密码**：`forgot-password` 防枚举（无论邮箱是否存在响应一致）+ 1h 一次性令牌邮件；`reset-password` 更新散列、清除令牌并踢下线全部会话，写入审计。
   - **账号注销**：`DELETE /api/auth/account` 软删除 + 踢下线 + 审计留痕；30 天冷却期内可由 Admin 恢复（同邮箱冲突返回 409），超期硬删级联（管理员账号豁免）。
   - **审计日志**：11 类安全动作全量写入 `user_audit_logs`，管理员经 `GET /api/admin/audit-logs` 分页查询；日志按留存策略自动清理，不会无限增长。
