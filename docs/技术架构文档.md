## 1. 源网站技术选型深度剖析 (Source Site Tech Stack Analysis)

经过对 **rabbithole.chat** 及其开源复现项目（如 Open RabbitHoles）的架构逆向与特征分析，其核心技术体系建立在**“现代 Web 前端技术栈 + 2D 拓扑图谱引擎 + 本地优先 (Local-First) 架构 + 流式大模型聚合”**的基础之上。

## 2. 渲染引擎方案对比与选型决策

在实现类似 RabbitHole 的无限画布时，业界主要存在三种渲染路径：

```
                    ┌─────────────────────────┐
                    │    无限画布渲染技术路线   │
                    └────────────┬────────────┘
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌──────────────────┐   ┌───────────────────┐   ┌───────────────────┐
│ 方案 A: 纯 Canvas │   │ 方案 B: DOM + SVG │   │ 方案 C: WebGL/GPU │
│ (如 Miro/Figma)   │   │  (RabbitHole 模式) │   │ (如 3D 图形可视化) │
└──────────────────┘   └───────────────────┘   └───────────────────┘
 优势: 极高渲染上限      优势: 文本与交互极强    优势: 几十万级海量点位
 劣势: 需自实现文本排版  劣势: 节点过万时需虚拟化 劣势: 维护成本高、交互差
```

### 选型结论：采用基于 `@xyflow/react` (React Flow v12+) 的混合渲染工业级方案
* **为什么说 React Flow 是最佳工业解法？**
  `@xyflow/react` 正是「DOM 节点 + SVG 贝塞尔图层」架构在 React 生态中最成熟的权威实现（被 RabbitHole、Open RabbitHoles、Dify、Langflow 全面采用）：
  * **节点层 (DOM)**：每个对话卡片都是标准 HTML/React 组件，原生支持鼠标划词文本选择 (Selection API)、输入框交互、Markdown 流式渲染与 Tailwind 样式；
  * **连线层 (SVG)**：React Flow 内部通过高性能 SVG Viewport 与 `<path d="M ... C ...">` 渲染平滑自适应的三次贝塞尔曲线 (`BezierEdge`)，拖拽与平移均由底层高度优化；
  * **开箱即用生态**：内置 `MiniMap`、`Controls`、`Background`、视口矩阵变换 Hook (`useReactFlow`, `screenToFlowPosition`)，免除从零手写坐标映射与手势边界的大量低效与易踩坑代码。

## 4. 关键算法与技术实现机制

### 4.1 免拖拽自动分层树形布局算法 (Zero-Drag Hierarchical Layout Engine)
> **核心交互升级**：用户使用思维画布的核心痛点是“把精力浪费在整理杂乱排版、对齐卡片和解决重叠上”。RabbitHole 采用**锁定拖拽 (`nodesDraggable: false`) + 自动化树形分层算法**：
> 1. 用户无需手动拖拽节点，所有节点位置由系统根据树形拓扑结构自动优雅排列；
> 2. 用户仅需通过鼠标/触控板平移与缩放画布浏览；
> 3. 当产生新分支（或划词深入）时，算法自动分配右侧最佳空位，并通过平滑运镜 (`setCenter` / `fitView({ duration: 800 })`) 引导视线聚焦。

#### 树形递归坐标排布原理 (Tidy Horizontal Tree Layout)
* **水平层级深浅（X轴）**：节点的 $X$ 坐标由其在思维树中的深度（Depth）决定：
  $$X = \text{Depth} \times (\text{NodeWidth} + \text{ColumnGap})$$
  例如卡片宽 420px，列间距 120px，则第 0 代节点 $X=0$，第 1 代子节点 $X=540$，第 2 代孙节点 $X=1080$。
* **垂直分支错落（Y轴）**：递归计算每个子树的总高度，父节点的 $Y$ 坐标垂直居中于其所有子节点的外接矩形中心：
  $$Y_{\text{parent}} = \frac{Y_{\text{first\_child}} + Y_{\text{last\_child}}}{2}$$
  当兄弟节点并列展开时，根据各卡片实际自适应高度并加上固定间隙（RowGap: 40px）自上向下推移，确保永不发生遮挡。
* **增量平滑动画**：布局重排时配合 CSS `transition: transform 0.4s cubic-bezier(0.16, 1, 0.3, 1)`，使整棵思维树如同生命体般自然向外舒展分支。

---

### 4.2 视口坐标与画布坐标映射算法 (Matrix Transformation)
在无限画布中，屏幕上的鼠标位置 $(X_{screen}, Y_{screen})$ 与节点在世界坐标系中的位置 $(X_{world}, Y_{world})$ 必须进行精准的仿射变换转换：

$$X_{world} = \frac{X_{screen} - Pan_X}{Zoom}$$
$$Y_{world} = \frac{Y_{screen} - Pan_Y}{Zoom}$$

反向映射（世界坐标转屏幕显示位置）：
$$X_{screen} = X_{world} \cdot Zoom + Pan_X$$
$$Y_{screen} = Y_{world} \cdot Zoom + Pan_Y$$

*通过 CSS `transform: translate3d(${pan.x}px, ${pan.y}px, 0) scale(${zoom})` 硬件加速图层，在 GPU 复合线程上完成整个画布视图的高性能位移。*

---

### 4.2 动态贝塞尔曲线连接算法 (Dynamic Cubic Bezier Routing)
当节点 $A$（起点）向子节点 $B$（终点）连线时：
1. **连接锚点计算**：起点位于节点 $A$ 右侧中点 $(A_x + A_{width}, A_y + A_{height}/2)$，终点位于节点 $B$ 左侧中点 $(B_x, B_y + B_{height}/2)$。
2. **三次贝塞尔控制点计算**：
   - 控制点偏移距离：$\Delta X = \max(|B_x - (A_x + A_{width})| \times 0.5, 60)$
   - $P_1 = (Start_x + \Delta X, Start_y)$
   - $P_2 = (End_x - \Delta X, End_y)$
3. **SVG 路径指令**：
   $$\text{d} = \text{"M } Start_x \text{ } Start_y \text{ C } P_{1x} \text{ } P_{1y}\text{, } P_{2x} \text{ } P_{2y}\text{, } End_x \text{ } End_y\text{"}$$
产生出如丝般顺滑、符合人体工学的自然曲线分支。

### 4.3 祖先上下文溯源聚合算法 (Ancestry Context Chaining)
传统聊天是线性的 `messages: [msg1, msg2, ...]`。在 RabbitHole 的 DAG 图中，子节点生成答案时必须回溯自己的祖先链：

```typescript
/**
 * 沿图谱的有向边向上回溯，重构出该节点的完整思维路径上下文
 */
export function resolveConversationHistory(
  targetNodeId: string,
  nodes: Record<string, CanvasNode>,
  edges: CanvasEdge[]
): Array<{ role: 'user' | 'assistant'; content: string }> {
  const chain: CanvasNode[] = [];
  let currentId: string | undefined = targetNodeId;

  // 避免环路死循环（防卫性编程）
  const visited = new Set<string>();

  while (currentId && !visited.has(currentId)) {
    visited.add(currentId);
    const node = nodes[currentId];
    if (node) {
      chain.unshift(node); // 祖先在先，子代在后
    }
    // 寻找指向当前节点的边 (source -> target)
    const incomingEdge = edges.find(edge => edge.targetNodeId === currentId);
    currentId = incomingEdge ? incomingEdge.sourceNodeId : undefined;
  }

  // 将节点链扁平化为标准多轮 LLM Prompt 消息列表
  return chain.flatMap(node => node.messages);
}
```

### 4.4 划词“钻入兔子洞 (Rabbit Hole)”交互实现
1. 用户在回答卡片内通过光标选中文本。
2. 监听 `selectionchange` / `mouseup` 事件，调用 `window.getSelection()` 获取选中的文字片段与 `Range`。
3. 获取 `Range.getBoundingClientRect()` 得到屏幕视口坐标。
4. 将该坐标逆运算换算为画布世界坐标 $(X_{world}, Y_{world})$。
5. 在母节点右侧偏移位置（如 $+380px$）自动实例化一个新节点，并自动创建一条带有“划选引用标签”的有向边。
6. 新节点预填充选中的文字为初始议题，自动获得焦点或直接向模型发出追问请求。

## 6. 技术实施路线演进

1. **第一阶段：自研高性能 DOM+SVG 画布核心引擎**
   - 实现无第三方重量级依赖的极轻量、极度可控的 Infinite Canvas。
   - 包含：平移、滚轮缩放、自适应居中、动态点阵、平滑贝塞尔曲线 SVG 连接。
2. **第二阶段：节点体系与划词分支 (Rabbit Hole Feature)**
   - 实现可拖拽卡片、输入交互、选择文本触发悬浮分支功能。
   - 祖先历史回溯与流式生成打通（Node.js 端通过 `@google/genai` 接入 Gemini API）。
3. **第三阶段：完整工具链与本地化沉淀**
   - 笔记节点支持、小地图联动、撤销重做历史快照 (Undo/Redo)、JSON/Markdown 导出。
