## 一、锁定的产品决策

| # | 决策项 | 结论 |
| :--- | :--- | :--- |
| 1 | 持久化策略 | 服务端为真源，未登录时本地仅作草稿 |
| 2 | 游客模式 | **砍掉**，强制登录 |
| 3 | 算力点数体系 | **砍掉**（credits / 流水 / 预检 / 调账 / 充值全部移除） |
| 4 | 用户档位 | 只有**体验版**与 **VIP** 两档 |

| 6 | VIP 到期语义 | 硬锁定：禁推理、禁建画板；保留只读 + 编辑便签 + 导出 |
| 7 | 支付 | 一期**不接**真实支付，做 `PaymentProvider` 抽象 + MockProvider |
| 8 | 一期 VIP 获取路径 | Admin 后台赠送 |
| 9 | 公开分享 | 二期 |
| 10 | 定价 | 周卡 ¥9.9 / 月卡 ¥24.9（2026-09-10 收口；年卡 ¥199 已下架，ADR-0014）|

## 二、产品权益矩阵

| 能力 | 体验版 | VIP |
| :--- | :--- | :--- |
| 画板数量 | 最多 **3** 个 | 无限 |
| AI 推理节点 | 每画板 **10** 个 | 无限 |
| 子分支导出为独立画板 | ❌ | ✅ |
| 响应队列 | 常规 | 高优先级（更高并发限流） |
| 高级模型（`is_vip_only`） | 不可访问 | 可访问 |
| VIP 到期后 | — | 禁推理 / 禁建画板；保留只读、编辑便签、导出 |

**VIP 到期降级规则**：到期即锁定 AI 推理与新建画板，但用户必须能把自己的成果完整带走 —— 浏览、编辑便签笔记、导出 JSON 与 Markdown 大纲全部放行。需配套到期前提醒与宽限期（天数待定，建议 3~7 天），避免到期瞬间锁死引发客诉。

## 三、一期里程碑

### A. 账号与数据：服务端为真源

**工作项**
- A1 删除 `/api/auth/guest` 路由与 `middlewares.ts` 自动开户分支，未登录一律 401
- A2 画布加载改走服务端；保存以 `POST /api/canvases/:id/save` 为主路径，失败回退本地
- A3 nodes + edges 批量保存事务化（当前为逐条写入）
- A4 乐观锁冲突检测（`updated_at` 或 version 字段）
- A5 断网降级 + 重试队列 + 可见的保存状态指示
- A6 未登录本地草稿 → 登录后合并策略

**验收标准**
- [x] 未登录访问任意 `/api/canvases/*` 返回 401，前端跳转登录页（`canvasesRouter.use(authMiddleware)`）
- [x] 换浏览器或设备登录后，节点、连线、折叠状态、颜色、便签、多轮 `messages` 零丢失（ADR-0025 载入以服务端为准）
- [x] 同一画布双标签页并发编辑，后保存方收到冲突提示，不静默覆盖（2026-09-18 起由 ADR-0026 单写者编辑锁取代：副标签只读，不再产生并发保存）
- [x] 断网期间编辑不丢数据，恢复网络后自动补传（sync-queue 持久化 + pagehide keepalive 补传）
- [x] 保存失败时前端有明确错误提示（syncState error/conflict + 顶栏提示 + `beforeunload` 拦截）

### B. 配额服务端化（最高优先级）

**工作项**
- B1 四条权益限制从前端 `if (isVip)` 全部下沉为后端中间件校验
- B2 新增「VIP 已过期」锁定态，与「体验版」区分开
- B3 到期前提醒横幅 + 宽限期
- B4 前端按服务端返回的状态渲染，区分「体验版已达上限」与「VIP 已过期」文案

**验收标准**
- [x] 直连 API（绕过前端）创建第 4 个画板被拒（`assertCanCreateBoard`）
- [x] 体验版在已满 10 个 AI 节点的画板发起提问被拒（`chatQuotaMiddleware`）
- [ ] 体验版调用子分支导出被拒 —— **未达标（2026-10-25 复核）**：导出入口对所有登录用户可见，闸门只有画板配额 `canCreate(isVip)`，服务端无 VIP 判据；付费版仅剩「无限画板」这一间接约束（技术债 #0105；待产品决定是补服务端权益位还是改口径）
- [x] VIP 过期后发起推理被拒，但读取画布、编辑便签、导出 JSON/Markdown 全部正常（`VIP_EXPIRED` 仅拦 chat）
- [x] VIP 过期前出现提醒横幅，宽限期内体验不中断（`GRACE_PERIOD_DAYS=7`）

### C. 清理算力点数体系

### D. 滥用防线（点数移除后的补位）

点数与限流原本是两道防线，移除点数后限流成为唯一闸门，本项不可省略。

**工作项**
- D1 IP 维度注册限流（防批量注册刷取 30 次生成额度）
- D2 保留并校准每分钟阶梯限流
- D3 邮箱验证，未验证账号不可使用 AI 推理

**验收标准**
- [x] 单 IP 单位时间内注册超过阈值被拒（5 次/小时/IP）
- [x] 未验证邮箱的账号发起推理被拒（403 `EMAIL_NOT_VERIFIED`）
- [x] 阶梯限流按角色生效，体验版 / VIP / Admin 阈值不同（25 / 60 / 120 次每分钟）

### E. 商业化骨架

## 五、明确不做

| 项 | 不做的原因 |
| :--- | :--- |
| 游客模式 | 决策已砍；强制登录 |

| 自研向量检索 / RAG 知识库 | 超出当前产品定位 |
