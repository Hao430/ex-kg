## 二、产品权益矩阵

| 能力 | 体验版 | VIP |
| :--- | :--- | :--- |
| 画板数量 | 最多 **3** 个 | 无限 |
| AI 推理节点 | 每画板 **10** 个 | 无限 |
| 子分支导出为独立画板 | ❌ | ✅ |
| 响应队列 | 常规 | 高优先级（更高并发限流） |
| 高级模型（`is_vip_only`） | 不可访问 | 可访问 |

### H. 安全加固补丁（2026-09-07，一期收官后画布删除链路专项）

**背景**（排查发现的四处缺陷）
1. **水平越权**：画布权限判定 `isClaimableCanvas` 对 `board-` 前缀（前端生成、毫秒时间戳可枚举）、`seed_` 前缀、`demo-user-1`/`guest_*` 属主无条件放行——任意登录用户可读/写（改属主）/删他人画布。
2. **删除与保存竞态复活**：前端 `deleteBoard` 不检查响应码即清本地（403/断网时远端画布保留，下次拉列表「复活」）；sync-queue 无 dequeue，删除后待同步的自动保存会把画布 upsert 写回。
3. **PG 分支异常吞噬**：`deleteCanvas` 的 catch 吞掉 ForbiddenError 后落内存分支，越权删除可能返回 200 假成功，违反「PG 成功 return / 失败落内存」双模模板本意。
4. **软删口径不统一**：`canvases.deleted_at` 列与 partial 索引早已存在但从未启用，删除为硬删，`canvas_delete` 审计指向已物理消失的行，且 upsert 可使已删画布复活。

**决策记录**
- 严格属主制：读/写/删一律属主本人或 admin；废弃全部「可认领」放行（guest 模式已删，seed/demo 来源已消失，`includeNoOwner` 为死代码）。
- 共享特例仅保留 `default-board`/`default-canvas`（全局共用同一行）；**默认板禁删**（软删会导致所有用户对该 id 永久 404，全局默认板锁死）。
- 软删启用：DELETE 改 `UPDATE ... SET deleted_at=NOW()`（与 F4 注销软删口径一致）；nodes/edges 子表即时物理清理（对齐原 CASCADE 语义）；saveCanvas 对已软删 id 抛 404 并在 upsert 加 `WHERE deleted_at IS NULL` 防并发复活；list/get/ownerInfo/search 六处查询补 `deleted_at IS NULL` 过滤；内存 CanvasRecord 同步加字段。
- 前端 `deleteBoard` 改确认制：仅 2xx/404 清本地 + dequeue；403/5xx/断网保留本地并 toast 提示；Topbar 对 default-board 隐藏删除按钮。
- 配额语义修订：严格属主制下「认领计配额」消亡，退化为纯新建计数（Spec B1 注释同步）。
- 明确不在本次范围：删除不存在画布的 404 语义（现为 200 `{success:false}`）、canvases 路由独立 limiter、软删行 retention 清理。

**修改文件**
`server/core/records.ts`、`server/repositories/canvas.repository.ts`（核心）、`server/services/canvas.service.ts`、`src/lib/sync-queue.ts`（+dequeue）、`src/lib/storage.ts`、`src/App.tsx`、`src/components/ui/Topbar.tsx`；新增测试 `tests/h1-canvas-tenant-softdelete.test.ts`（18 用例：越权矩阵/共享回归/禁删/软删/防复活/审计/配额释放/前端确认制/dequeue）。

### I. 来源索引（Grounding）链路修复（2026-09-07）

**背景**（排查发现的八处缺陷）
1. 联网开关为纯摆设：前端发送 `enableWebSearch` 被 zod 静默剥离，后端 web_search 恒开；开关 UI（ModelSearchSettingsModal）是无入口的死组件。
2. 审计与配额失真：前端不传 `canvasId/nodeId` → `ai_request_logs` 归因字段恒 null；`chatQuotaMiddleware` 拿不到 canvasId → 体验版「每画板 10 个 chat 节点」上限在 UI 链路上永不触发（配额绕过）。
3. 千问路径丢来源标题/片段：`collectSources` 只读 `s.url`，title 一律用域名伪造，`snippet` 类型声明存在但全链路无人填充（与 Gemini 路径信息量不对等）。
4. 正文 `[n]` 角标与来源列表编号无对齐约定（API 不支持自动角标，模型自行编号）。
5. 产生侧零测试：SSE 解析/去重/审计无覆盖；roundtrip 夹具为旧形状 `{title,url}`。
6. 来源无数量上限，节点数据可膨胀。
7. Gemini 容灾换流（`reset`）后前端不清旧来源，出现「文本无来源、列表留旧来源」错位。
8. 来源 `href` 未做协议白名单；内存 getCanvas 与 PG 输出归一化不一致。

**决策记录**
