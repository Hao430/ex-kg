# ADR-0025: 载入以服务端为准，删除冲突副本子系统

- **Status**: Accepted
- **Date**: 2026-09-18
- **Deciders**: 枝想架构组
- **Tags**: sync, conflict, persistence, canvas

> 本 ADR **修订 ADR-0021**：保留其「服务端权威 + 本地未确认缓冲」的主体，但移除载入路径的
> 本地保护与冲突副本安全网，并把「未同步判据」统一到节点级差分。

## Context and Problem Statement

ADR-0021（服务端权威同步）与 ADR-0017（节点级合并与墓碑）落地后，同一件事——「本地与云端
分叉了没有」——在系统里仍有**两套精度不同的判据并行**：

| 路径 | 判据 | 精度 | 分叉时怎么做 |
| :--- | :--- | :--- | :--- |
| 保存（`syncBoardToBackendInner`） | `computeOps(base, 本地 blob)` 节点级差分 | 节点/边 | 服务端 `mergeWriteCanvas` 合并、墓碑胜出，**不产生副本** |
| 载入/切换（`adoptServerVersion`） | `boardStore.isDirty` 布尔 + 整板 `serverUpdatedAt` 字符串 | 整块板 | 二选一保护不住就 `preserveLocalAsConflictCopy()` **复制一整块板** |

线上实测（owner 反馈 + 排查确认）：**多设备 / 多标签页编辑过同一块画板后，列表里会莫名多出
一块「(冲突副本)」画板**。两设备改的往往是**不同节点**，保存路径本可无损合并，载入路径却只看到
「整板版本号对不上」，判定为真冲突并复制一整块。

同一个根因还派生出两个缺陷：

1. **`dirty` 是手工维护的派生状态，双向漂移**：
   - 假脏：`saveBoard()` 无条件置脏，而画布变更回调对量测/选中/拖动一视同仁；保存侧算出空差分后
     提前返回、**不经过 `confirmServerSave`**，`dirty` 永不清 → 只是「打开过画板」也长期算未同步；
   - 假干净：保存飞行期的新编辑不被重新置脏（`confirmServerSave` 无条件清标记、基线只推进到已上行
     快照），此时任何载入都会因「非脏」用云端内容覆盖本地 blob，**静默丢掉飞行期编辑**。
2. **缺基线时误删他端节点**：`seedBaseFromServer` 把基线设成服务端当前全量，本地 blob 若落后，
   `computeOps` 会把「服务端独有 id」判成本地删除 → 反过来删别人的内容。这违反 `board-ops.ts`
   声明的「基线里的 id 必然是本设备见过的」不变量。

**关键事实：冲突副本保护的是「本地未上传内容」，而它在整板替换时代才是必需的。** ADR-0017 之后
「本地胜出」不再等于「覆盖他端」（只上行自己改过的节点），副本作为安全网已经过时；它保护的粒度
（整块板）也比实际分叉粒度（节点）粗。

## Decision Drivers

- **用户可见症状**：重复画板（副本）比「同节点后到者覆盖」更伤信任，且副本本身是本地资产，
  上传失败就只活在那台浏览器里。
- **判据必须单一**：同一概念两套表示必然分叉（现存的两处漂移就是证明）。
- **产品已接受无网代价**：ADR-0021 已明确「无网即不可编辑」，因此不必为离线保留本地裁决。
- **不引入新依赖**：不引入 CRDT/Yjs；服务端零改动是重要约束（迁移已移出应用进程，ADR-0019）。

## Considered Options

- **Option A: 保留副本，只修判据** — 把 `dirty` 换成差分派生，仍在真分叉时另存副本。
- **Option B: 合并优先，删除副本** — 载入时把本地未上行差分交给合并上传，不复制整块板。
- **Option C: 载入以服务端为准，本机未上行内容直接丢弃**（已选） — 载入不做裁决，取到即采用。

## Decision Outcome

**Chosen option: "C"**。产品拍板：**服务端是唯一真相，载入时本机未上行内容直接丢弃。**

- **A 被否**：仍然用「一整块板」去承载一个「几个节点」的分叉，重复画板的问题只是变稀，不会消失。
- **B 被否**：能力上更优（异节点编辑无损），但保留了「本机也有话语权」的裁决面与合并上传窗口，
  与「服务端唯一真相」的口径不一致；owner 明确选择不做本地保护。

### 具体落地

1. **载入即采用**（`src/lib/storage.ts` `fetchBoardFromServer`）：
   - GET 2xx → 覆盖本地 blob、把差分基线重置为服务端状态、清未同步标记、**作废在途保存**；
   - GET 404 → 返回 null，**保留本地**（服务端没有这一行：纯本地草稿 / 首次保存还没落库的新板）；
   - 非 2xx / 网络失败 → 返回 null，保留本地画面（拿不到服务端内容就无从采用）。
2. **删除冲突副本子系统**：`preserveLocalAsConflictCopy`、副本 id 派生、复用表、
   `adoptServerVersion` 的整板裁决、`conflictCopyId` 事件字段、副本 UI 文案与埋点，全部移除；
   历史孤儿键 `deepdive_conflict_copy_*` 在 `bindScope` 时清理。
3. **409 仅作防御**：v2 客户端走节点级合并、服务端刻意不校验画板级乐观锁（ADR-0017），正常永远
   到不了；能到这里的只有旧协议客户端/配置不一致，故按确定性拒绝（`rejected`）处理并提示刷新。
4. **在途保存作废**（`contentEpoch`）：载入采用服务端内容后，更早发出的保存回包若到达，不得推进
   基线——否则会把刚重置成服务端状态的基线打回旧值，之后所有差分都是错的。
5. **缺基线不发墓碑**：保存路径走过 `seedBaseFromServer` 补拉时，本次请求清空
   `deletedNodeIds`/`deletedEdgeIds`（缺基线时无法区分「本地删除」与「本设备没见过」）。
6. **空差分收敛**：`isEmptyOps` 早退分支清掉未同步标记（不发请求即与基线一致）。

### Positive Consequences

- **重复画板消失**：不再有任何路径会复制出一块「(冲突副本)」。
- **裁决面收敛**：「本设备改了什么」的唯一权威是差分基线 + 本地 blob；载入路径不再读 `dirty`。
- **误删他端节点的隐患关闭**（缺基线路径）。
- **服务端零改动、无迁移、无新依赖**，纯客户端即可上线。

### Negative Consequences

- **本机未上行的内容在载入时静默丢弃**（离线编辑、弱网/刷新前没传完的编辑）。这是 ADR-0021
  「无网不可编辑」的彻底化，但**当前 UI 只有泛化的「同步失败」，没有「有未保存内容将被丢弃」的
  口径**——登记为技术债（#0096）。
- **不再有副本安全网**：同节点并发编辑仍是「后到者覆盖」，且不再有第二份留存（该取舍在 ADR-0017
  已被接受，但副本曾提供过一层额外保险）。
- **同一浏览器多标签页**共享 blob/基线，同时编辑同一块板仍可能互相覆盖（含把对方刚保存的节点
  误判为本地删除）。登记为技术债（#0097）。
  - ✅ 补记（2026-09-18）：已由 **ADR-0026**（单写者编辑锁，`BroadcastChannel`）收口——第二个标签
    对该画板不再渲染编辑画布。技术债 #0097 已 Done。

### Follow-up / Mitigation

- ✅ **「离线 / 有未保存内容」的 UI 口径已落地**（2026-09-18，技术债 #0096 已 Done）：断网时
  toast + 顶栏红云「当前无网络，改动暂时无法保存到云端」；进入慢速自愈（`error`）时补一次
  toast 与文案「有改动尚未保存到云端（已停止自动重试）」；`unsavedDiscardRisk = 有未确认内容 &&
  (离线 || error || conflict)` 时，切换画板/新建画板/导入备份前 `window.confirm` 拦截，风险态下
  注册 `beforeunload` 拦刷新/关闭。**无风险时不弹**，不打扰正常使用。
- ✅ **缩短「未上传窗口」已落地**（2026-09-18）：自动保存分两条通道——内容类变更（打字、AI 流式
  回答）仍走 600ms 防抖；**结构操作与提交点立即落库**。判据是「节点/边 id 集合是否变化」
  （`src/lib/canvas-change.ts`，纯函数 + 单测），覆盖新增/删除节点或边、连边（id 集合变化即触发）；
  另有三个显式提交点：拖拽结束、便签/标题失焦、折叠切换。
  意义：结合「载入以服务端为准」，未上传窗口里一旦丢内容就是永久丢，故窗口越短越好。
- ✅ **离开/隐藏前的收口已落地**（2026-09-18）：光把窗口压小还不够，以下三处仍会把窗口内的
  改动留成永久丢失，已逐一堵上——
  1. **切换画板 / 删除其他画板 / 导入备份前**先 `flushPendingCanvasSave()`：紧接着的重挂载会让
     新板的变更清掉待发定时器，那段改动只存在于内存里；
  2. **页面隐藏/卸载前**先 flush 再 `flushForPageHide`：keepalive 补传读的是**已落盘的
     blob**，不先落盘就等于把旧内容又发了一遍，最后几百毫秒照样丢；
  3. **AI 流式回答**按 2s 强制立即落盘（`STREAM_FLUSH_INTERVAL_MS`），提问一进节点、定稿、
     失败三个时刻也立即固化，并在组件卸载时 `abort` 掉流。这条最值钱：回答是花 token 换来的、
     不可复现，而服务端只落审计日志、**不保存节点内容**，生成中途切走原本会整段丢失。
- 多标签协调（技术债 #0097）：候选方案为 BroadcastChannel/storage 事件同步、单标签编辑锁，或给
  `BoardOpsBase` 加 per-tab nonce 以抑制墓碑。
- 观测：新增 `canvas_load`（`branch: adopt|notfound|offline`）；服务端
  `[canvas-save] 409 CANVAS_SAVE_CONFLICT` 的 warn 计数应持续为 0。

## Pros and Cons of the Options

### Option A: 保留副本，只修判据

- **Good**：改动最小；仍然「两边都不丢」。
- **Bad**：粒度错配未解决——异节点分叉仍被当成整板分叉；副本上传失败的存量问题仍在。

### Option B: 合并优先，删除副本

- **Good**：异节点编辑无损合并；画面上不会出现重复板。
- **Bad**：载入路径仍保留「本机未上传差分」这一裁决面与合并上传窗口，与「服务端唯一真相」不彻底一致。

### Option C: 载入以服务端为准（已选）

- **Good**：裁决面最小、语义最直白；重复画板与误删隐患一起消失；服务端零改动。
- **Bad**：放弃离线保护；同节点并发仍是静默覆盖；多标签仍不安全。
