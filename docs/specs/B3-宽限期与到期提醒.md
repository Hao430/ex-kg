# Spec B3+B4 — VIP 到期宽限期 + 提醒横幅 + 前端文案区分

> 来源：`docs/里程碑与分期规划.md` B 组 B3/B4、验收「VIP 过期前出现提醒横幅，宽限期内体验不中断」
> 状态：本轮实施，B 组收尾

## 1. 宽限期语义（对决策 #6 的落地细化）

- 常量 `GRACE_PERIOD_DAYS = 7`（原待定项 #1 取建议值上限）
- 有效身份三段：
  - `vip_expires_at` 为空或 > now → VIP 有效（无提醒）
  - now − 宽限期内（`expired < now ≤ expired + 7d`）→ **宽限期**：体验不中断（推理/建板放行），`vipExpired: true` + `vipGraceDaysRemaining` 供横幅提醒
  - 超过宽限期 → 硬锁定（plan 'trial'，推理/建板 403 `VIP_EXPIRED`）
- `effectiveEntitlements` 输出扩展 `vipGraceDaysRemaining?: number`；`/api/auth/me` 透传

## 2. 前端（B4）

- `AuthUser` 增加 `entitlements?`；AuthContext 直接透传 `/me` 返回
- `App.tsx` 画布视图顶部横幅（vBanner）：
  - **即将到期**（VIP 有效且剩余 ≤3 天）：黄色「VIP 将于 X 天后到期，请及时续费」+ 续费按钮
  - **宽限期**：橙色「VIP 已过期，宽限剩余 X 天，到期后将无法推理与新建画板」+ 续费按钮
  - 横幅可手动关闭（sessionStorage 记忆当天不再提示）
- 配额 403 文案：服务端返回的中文文案已经区分两种状态（B1），前端 toast 直接透传（A5/B1 已具备），本轮补 chat 流的 403 提示——chat 为 SSE，403 在建连前已返回 JSON，前端 chat 调用处如已处理 error 事件则透传（核对现有处理，缺则补）

## 3. 测试先行（`tests/b3-grace.test.ts`）

1. VIP 到期 3 天内：entitlements = { plan 'vip', vipExpired true, vipGraceDaysRemaining 3 }，推理不被 403 VIP_EXPIRED
2. VIP 到期 7 天整：宽限期最后一天，仍放行
3. VIP 到期 8 天前：plan 'trial'，推理 403 VIP_EXPIRED
4. VIP 有效（未来 30 天）：vipExpired false，无 grace 字段
