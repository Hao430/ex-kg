# Spec D1+D2 — IP 注册限流 + 阶梯限流校准

> 来源：`docs/里程碑与分期规划.md` D 组 D1/D2、待定项 #2；验收「单 IP 单位时间内注册超过阈值被拒」「阶梯限流按角色生效，体验版 / VIP / Admin 阈值不同」
> 状态：本轮实施（D3 邮箱验证下一轮）

## 1. 现状

- 登录已有 15 次/分/IP 限流；chat 已挂角色阶梯限流（体验版 25 / VIP 60 / Admin 120 每分钟，按 user_id 或 IP 计数）
- **sign-up 无任何限流**——点数移除后配额是唯一闸门，批量注册可直接刷取体验额度（D1 缺口）

## 2. 设计

- **D1**：新增 `signupRateLimiter`——每 IP **5 次/小时**（express-rate-limit，`ipKeyGenerator` 计数），挂载 `POST /api/auth/sign-up`；超限返回 429 `RATE_LIMIT_EXCEEDED`。阈值原待定，本 spec 定为 5/h 并更新里程碑待定项 #2
- **D2**：现有阶梯限流数值（25/60/120）与文档一致，视为校准完成；本轮补测试锁定行为（体验版第 26 次 chat 429、Admin 同窗口 30 次不 429，证明阈值按角色差异化）

## 3. 测试先行（`tests/d1-ratelimit.test.ts`）

1. 同 IP 连续 6 次 sign-up → 第 6 次 429 RATE_LIMIT_EXCEEDED
2. 体验版连续 30 次 chat → 出现 429（阈值 25）
3. Admin 连续 30 次 chat → 无 429（阈值 120，角色差异化）
