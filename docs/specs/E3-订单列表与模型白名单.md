# Spec E3+E4 — Admin 订单列表 + is_vip_only 模型白名单

> 来源：`docs/里程碑与分期规划.md` E 组 E3/E4；E4 验收「is_vip_only 模型对体验版不可见，直连 API 亦被拒」
> 状态：本轮实施，E 组收尾

## 1. E3 — Admin 订单列表

- `billing.repository` 新增 `listAllOrders({ page, limit, status? })`：双模分页（PG COUNT+ORDER BY created_at DESC；内存过滤排序切片）
- `admin.service` 透传；`admin.ts` 新增 `GET /api/admin/orders?status=&page=&limit=`（requireAdmin）
- 前端 `AdminDashboardModal` 新增「订单」Tab：订单号/用户邮箱/套餐/金额/状态/时长/创建时间，分页浏览

## 2. E4 — is_vip_only 模型白名单

- `AiModelConfig` 新增 `vip_only_models?: string[]`（存 system_settings 的 ai_model_config）
- admin model-config PUT zod schema 增加该可选字段（数组透传保存）；GET 返回
- `chatQuotaMiddleware`：体验版/过期 VIP 请求体 `model` 命中白名单 → 403 `MODEL_VIP_ONLY`（VIP/Admin 不限）
- 测试覆盖「直连 API 亦被拒」（测试即直连）

## 3. 测试先行（`tests/e3-e4-orders-models.test.ts`）

1. Admin GET /api/admin/orders → 200，含已创建订单；?status=pending 过滤生效
2. 非管理员 GET /api/admin/orders → 403
3. Admin PUT model-config 带 vip_only_models → 200；GET 回读一致
4. 体验版 chat 指定白名单模型 → 403 MODEL_VIP_ONLY；VIP 同模型 → 非 403
5. 未命中白名单模型 → 体验版可正常走既有链路
