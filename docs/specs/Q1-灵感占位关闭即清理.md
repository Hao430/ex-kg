# Spec Q1 — 灵感开关改为画板级（服务端真源）：关闭即清理

> 来源：用户工单——「灵感滑块用于隐藏/展示灵感节点，但即使隐藏，灵感节点仍对布局产生影响（只是隐藏没有删除，占位在那里）。考虑关闭灵感就是直接删除」；拍板：删除当前画板占位 + 停止生成，且**滑块状态跟着画板走**。
> 状态：已实施（2026-09-17）
> 关联：ADR-0017（节点级合并 + 墓碑不可复活）、ADR-0018（共享默认板转型）、#0082（云优先收口：本地只作绘制缓存）、#0090（`status` 由客户端提供）、I 组口径（占位不计配额/节点墙）、O1（命令 ref 桥先例）、P1（同批工单）

## 1. 问题与现状

1. **开关是纯视图过滤**：为假时只给 `status==='suggested'` 的节点及边注入 ReactFlow `hidden: true`，`nodes/edges` state 原样保留。
2. **布局不理会 `hidden`**：自动布局是自家 dagre（`src/lib/layout.ts`），喂进去的是**完整** nodes/edges；占位估算尺寸 290×140 照常参与 `nodesep/ranksep`——「隐藏了但位置还空着」，这就是工单描述的症状。
3. **生成从来没停**：`spawnSuggestedNodes()` 在每次回答完成后**无条件**调用，全文件只有渲染处消费开关。关着灵感，每个新回答照样生成 3 个占位、照样入库、照样同步。
4. 删除链路已具备（`executeDeleteNodeIds` → 差分出 `deletedNodeIds` 墓碑），但**墓碑不可复活**：upsert 带 `WHERE deleted_at IS NULL`（ADR-0017）⇒「关闭即删除」**没有撤销余地**。
5. 不会误删进行中的回答：点击占位立刻置 `status='generating'`（`generateNodeAnswer` 首段），按 `status==='suggested'` 过滤天然只命中**未激活**占位；再叠加「无子节点」守卫即完全排除误删。
6. ⚠️ **实施中的一次纠偏**：初版把画板级开关做成了 localStorage 偏好。这违反本仓既定口径——**画板级状态一律服务端真源，本地只作绘制缓存/待确认投影**（#0082；`isFavorite`/`isArchived`/`folderId` 走 `PATCH /api/canvases/:id/meta` 的先例）。本地偏好会让同一块板在两台设备上各记各的，正是要避免的本地/服务端分叉。**终版为服务端列。**

## 2. 目标与非目标

**目标**

1. 开关为**画板级属性**，存服务端（`canvases.suggestions_enabled`），客户端经既有 meta 通道读写、以服务端回包为准。
2. 「关闭灵感」= 清理**当前画板**上所有未激活占位（确认后执行，走既有删除链路落墓碑）+ **本画板不再生成**新占位。
3. 清理后立即重排，空缝消失。
4. 交互与文案诚实：明确告知删除不可恢复；取消则开关保持开启、零改动。
5. 「关闭但有占位」的例外态（历史数据/他端先关闭）给显式清理入口，**不静默删数据**。
6. 判据抽成纯函数，可单测；服务端字段有 API 级往返测试。

**非目标**

- **不用任何本地偏好（localStorage）裁决该开关**。
- 不做撤销/回收站：墓碑协议下被删 id 无法复活，「撤销」只能重建成新 id（等于新占位），属伪功能。
- 不动配额口径、不动「点击占位 → 生成回答」链路、不改便签等其他节点类型行为。
- 不为共享默认画板（legacy）开特例：那块板的 meta PATCH 本就 403（见 §5）。

## 3. 设计

### 3.1 生成闸门

`spawnSuggestedNodes` 开头早退：`if (!suggestionsEnabled) return;`（并进 `useCallback` 依赖）。

语义：开启只影响**之后产生的新回答**是否附带占位；关闭状态下本画板不再产生任何新占位。这是「关了省事」的另一半——否则刚清理完又长出来。

### 3.2 服务端字段（真源）

- `canvases.suggestions_enabled BOOLEAN DEFAULT TRUE`（`schema.ts` 建表 + `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`；生产由**部署期 migrate** 落列，旧行取默认 TRUE ⇒ 行为与升级前一致）。
- `CanvasRecord.suggestionsEnabled`；`listCanvases`/`getCanvas`/`updateCanvasMeta` 三处双模映射统一 `?? true`（兼容未迁移的旧行）。
- `CanvasMetaPatch` + `PATCH /api/canvases/:id/meta` zod 白名单加 `suggestionsEnabled`（并入「至少一个字段」refine）。授权沿用既有严格属主制，**不开新口子**。
- 前端：`DeepDiveBoardMeta.suggestionsEnabled` 随列表快照下发；写入走 `updateBoardMetaLocally` → sync-queue 的 `meta` 操作 → PATCH，本地仅作待确认投影（`metaDirty`），服务端回包由 `confirmServerMeta` 收敛。**不写 localStorage 偏好**。

### 3.3 关闭流程（唯一有副作用的路径）

1. 顶栏开关**分方向**处理（`App.tsx` 的 `toggleSuggestions`）：
   - 开 → 关：不直接改状态，经命令 ref 桥 `requestDisableSuggestionsRef` 请求画布「确认并清理」（O1 的 ref 桥先例）。
   - 关 → 开：无副作用，直接经 meta 通道置 `true`。
2. 画布侧用纯函数 `collectSuggestedLeafIds(nodes)`（`src/lib/suggestions.ts`）收集待清理 id：`data.status === 'suggested'` **且无子节点**（异常态跳过并保留——宁可留着也不误删用户内容）。
3. 无可清理项 → 直接回调 App（经 meta 通道置 `false`），toast「已关闭探索灵感」。
4. 有待清理项 → 确认框：文案明示将删除本画板 N 个灵感节点、**不可恢复**、之后本画板新回答不再生成；
   - 取消 → 清空待办、**不改状态**（开关弹回开启），零改动；
   - 确认 → `executeDeleteNodeIds(ids)` → `applyLayout()` → 回调 App 落 `false` + toast「已清理 N 个灵感节点」。
5. `applyLayout()` 必须有：只删节点不重排，剩余节点沿用旧坐标，缝还在（`applyLayout` 是手动调用型）。

### 3.4 例外态：已关闭但仍有占位

来源：该板在关闭前留下的历史数据，或他端清理未完成。此时渲染层继续按 `hidden` 隐藏（过渡态兜底，注释写明它**不解决布局**），画布左上角显示「本画板还有 N 个灵感节点（灵感已关闭）」+「清理」按钮，点了走 §3.3 的同一确认流程。

**不做打开即静默清理**：删除不可恢复，批量删除必须经用户确认。

### 3.5 文案

- tooltip：开时「关闭后会清理本画板上的灵感节点，且不再生成（删除后不可恢复）」；关时「开启后本画板的新回答会附带灵感节点」；共享默认画板「共享默认画板不支持该设置」（开关禁用）。
- `aria-label` 同步；`data-testid="suggestions-toggle"` 不变；面向用户不出现内部术语。

## 5. 风险与已知边界

- **不可恢复**（高，已由确认框 + 文案兜住）：误点确认即永久删除该板占位；占位是 AI 生成的建议问题、不含用户输入内容，重新提问即可再生成。
- **共享默认画板（legacy）不支持**（中，**前置禁用**）：`updateCanvasMeta` 对 `isSharedDefaultCanvas` 直接 403（个人偏好写共享行无语义），故该板上开关禁用并给出说明，不产生「点了没用」的静默失败。ADR-0018 切 `private` 后它退化为普通画板即可用。
- **旧行/未迁移库**（低）：`?? true` 兜底，行为与升级前一致；生产缺列时 PATCH 会在部署期 migrate 之前报错——按手册先迁移后重启（Step 4.5）。
- **重排改变剩余节点坐标**（低）：`applyLayout()` 重算全图并因此标脏上传；本项目是 zero-drag 自动布局，坐标为派生数据。
- **`#0090` 相关**（低）：`status` 由客户端提供，恶意客户端可伪造 `status:'suggested'` 躲过节点墙——本次不改该口径。
