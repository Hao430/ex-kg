# Spec L1 — 画板库（检索 + 收藏/归档）+ 单层分组

> 来源：ADR-0015《画板管理采用「检索 + 收藏/归档 + 单层分组」》；产品诉求「画布多起来不好管理」
> 状态：已实施（Phase 1 收藏/归档/画板库、Phase 2 单层分组主体；Topbar 下拉内分组小标题为后续项）
> 关联：A5 重试队列、A2 服务端加载、B1 配额、H1 属主制、K2 分享

## 1. 目标与非目标

**目标**

1. 用「画板库」页替代单一顶栏下拉，支持按名称搜索、按最近/名称排序、按收藏/分组/归档筛选。
2. 收藏（置顶）与归档（收纳）跨设备同步，复用已建的 `is_favorite` / `is_archived` 列。
3. 单层分组：每块画板至多归属一个分组，分组不可嵌套；删除分组只解除归属，不删画板。
4. 全部管理操作兼容 local-first：离线可见、可改，联网自动补同步。

**非目标（本期不做）**

- 任意层级/嵌套文件夹、跨分组引用、分组内拖拽排序（`sort_order` 仅保留字段不做 UI）。
- 跨画板的节点全文检索（属二期「标签 + 全文检索」，本期搜索仅按画板名/分组名，前端内存过滤）。
- 归档释放配额。
- 分组离线创建/改名/删除（首版在线优先；移动画板离线可用）。完整离线分组 CRUD 列为后续项。

## 2. 分阶段

| 阶段 | 内容 | 数据模型变更 |
| :--- | :--- | :--- |
| **Phase 1** | 画板库页 + 收藏 + 归档 + 搜索/排序 | 无（列已存在） |
| **Phase 2** | 单层分组（CRUD + 画板移动 + 库页侧栏 + 下拉分组） | 新增 `folders` 表 + `canvases.folder_id` |
| **Phase 3（非本期）** | 标签 + 全文检索（原二期排期） | 激活 `tags` / `canvas_tags` |

## 3. 数据模型

### 3.1 Phase 1：无新表

`canvases.is_favorite` / `is_archived` 已建（`server/core/schema.ts:88-89`）。注意 CREATE 分支未加 `NOT NULL`，仓储读取统一 `COALESCE(is_favorite, FALSE)`，内存分支缺失时取 `false`，保证双模归一。

`CanvasRecord`（`server/core/records.ts:107`）与前端 `DeepDiveBoardMeta`（`src/types.ts:59`）扩展：

```ts
// CanvasRecord / DeepDiveBoardMeta 共同新增（可选，向后兼容旧 localStorage 条目）
isFavorite?: boolean;
isArchived?: boolean;
folderId?: string | null;   // Phase 2
```

### 3.2 Phase 2：folders 表（单层）

`server/core/schema.ts` 新增（与 `docs/数据库建表脚本.sql` 同步）：

```sql
CREATE TABLE IF NOT EXISTS folders (
  id VARCHAR(64) PRIMARY KEY,                 -- 客户端 UUIDv7（src/lib/uuid.ts）
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(64) NOT NULL,
  sort_order INT DEFAULT 0 NOT NULL,
  created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_folders_user ON folders(user_id);

ALTER TABLE canvases
  ADD COLUMN IF NOT EXISTS folder_id VARCHAR(64) REFERENCES folders(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_canvases_folder
  ON canvases(folder_id) WHERE deleted_at IS NULL;
```

- **无 `parent_id`**：从 schema 层杜绝嵌套。
- `ON DELETE SET NULL`：删分组只解除归属，绝不级联删画板。
- 不做软删：分组不承载内容，硬删仅丢分类；画板与节点/边完全不同，无需 30 天回收站语义。
- 内存分支：`inMemoryStore.folders: Map<string, FolderRecord>`（`server/core/memory-store.ts:8-22`），并给内存 `canvases` 记录补可选字段。

## 4. 服务端设计

### 4.1 新增/变更端点

| 方法 | 路径 | 说明 | 权限 |
| :--- | :--- | :--- | :--- |
| PATCH | `/api/canvases/:id/meta` | 改收藏/归档/标题/分组归属（轻量，不上传 nodes/edges） | 属主或 admin |
| GET | `/api/folders` | 当前用户分组列表 | 登录 |
| POST | `/api/folders` | 新建分组 | 登录 |
| PATCH | `/api/folders/:id` | 改名 | 分组的属主 |
| DELETE | `/api/folders/:id` | 删除分组（画板解除归属） | 分组的属主 |
| GET | `/api/canvases` | SELECT 增加 `is_favorite, is_archived, folder_id` | 现状不变 |

**PATCH meta** 是本 spec 的关键端点：不能复用 `/save`，否则收藏/归档会连带全量上传节点、并按乐观锁走内容冲突链路。定义：

```ts
// server/routes/canvases.ts
const UpdateCanvasMetaSchema = z.object({
  title: z.string().min(1).max(120).optional(),
  isFavorite: z.boolean().optional(),
  isArchived: z.boolean().optional(),
  folderId: z.string().max(64).nullable().optional(),
}).refine((v) => Object.keys(v).length > 0, { message: '至少一个字段' });
```

响应 `{ success: true, canvas: { id, updatedAt, isFavorite, isArchived, folderId, title } }`。**必须回传最新 `updatedAt`**： canvases 上的 `set_timestamp_canvases` 触发器会令任何 UPDATE 推进 `updated_at`，前端需据此推进乐观锁版本，否则下一次内容保存会 409（虽有自愈，但徒增往返）。

**分组归属校验**（防跨租户串联）：`folderId` 非空时，目标分组的 `user_id` 必须等于**画板属主** `canvases.user_id`，而不是请求者。即：admin 可以改他人画板的 meta，但不能把他人画板塞进自己的分组。

### 4.2 仓储（双模模板）

`server/repositories/canvas.repository.ts` 新增：

- `updateCanvasMeta(id, patch, userId, isAdmin): Promise<CanvasRecord>` — 属主校验（复用 `deleteCanvas` 同款：非属主抛 `ForbiddenError`，软删/不存在抛 `NotFoundError`），PG UPDATE 后回读 `updated_at` 等字段。
- `listCanvases` SELECT 增列，映射时 `COALESCE` 归一。

`server/repositories/folder.repository.ts`（Phase 2，新文件）新增 `listFolders(userId)`、`createFolder`、`renameFolder`、`deleteFolder(id, userId)`。全部照 CODEBUDDY 双模约定：PG try → 业务错误（`ForbiddenError`/`NotFoundError`）落内存前 **rethrow**；无 pool → 内存分支，输出字段与 PG 归一。

### 4.3 服务与路由

- `server/services/canvas.service.ts`：`updateUserCanvasMeta(...)`（含 meta 变更审计事件，可选）。
- `server/services/folder.service.ts` + `server/routes/folders.ts`，在 `server/app.ts` 挂载 `/api/folders`。
- 错误码：越权分组操作 `FOLDER_FORBIDDEN`，分组不存在 `FOLDER_NOT_FOUND`，跨租户 `folderId` 抛 `ValidationError`（400）。

## 5. 前端设计

### 5.1 类型与列表真相（board-store 扩展）

`DeepDiveBoardMeta` 增可选字段后，`board-store` 需要区分**内容脏**（现有 `dirty`）与**元数据脏**（收藏/归档/分组，新增 `metaDirty`）：

```ts
// src/lib/board-store.ts
let metaDirty = new Set<string>();          // 待同步的 meta 变更
```

合并规则（`recompute`）改为：`(dirty.has(id) || metaDirty.has(id)) && local ? local版 : 服务端版`。`hydrateFromServer` 中，`dirty` 或 `metaDirty` 命中的条目**不得被服务端快照覆盖**，待 PATCH 成功后以服务端回包收敛。

新增 mutator：`updateMetaLocal(id, patch)`（合并进 `localIndex`、加 `metaDirty`、`recompute`、持久化）、`confirmServerMeta(id, serverMeta)`（清 `metaDirty`、写回权威字段、`recompute`）。`addTombstone` / `confirmServerDelete` / `reconcileRemoteDeletion` / `bindScope` 同步清理/载入 `metaDirty`，持久化键走 `board-scope` 新增 `metaDirtyKey()`。

`board-store` 依赖边界不变：仍只依赖 `board-scope`（`.dependency-cruiser.cjs` 会校验）。

### 5.2 同步队列升级（本 spec 最大风险点）

现状 `sync-queue` 是「一板一任务」`Map<boardId, QueueTask{type: upload|delete}>`，`enqueueDelete` 直接覆盖 upload（防删后复活）。新增 `meta` 意图后，同一画板可能同时有「内容上传」和「收藏/分组」两个待办，必须升级为「一板多操作」：

```ts
export type QueueOp = 'upload' | 'delete' | 'meta';
export interface QueueTask {
  boardId: string;
  ops: QueueOp[];        // delete 独占并压制其余
  attempts: number;
}
```

- `enqueue` / `enqueueMeta` / `enqueueDelete` 按以下不变式维护 `ops`：
  - 若 `ops` 含 `delete`：忽略新的 `upload`/`meta`（删除压制一切）。
  - `enqueueDelete`：置 `ops = ['delete']`。
  - `enqueue` / `enqueueMeta`：追加；若已有 `delete` 则 no-op。
- `runOne` 执行顺序：**meta → upload**（先 PATCH 拿到新 `updatedAt` 再带锁上传内容，避免无谓 409）。按 op 收集结果：`ok`/`conflict` 出列，`fail` 保留；`ops` 空则任务完成，否则按现有指数退避重试（`MAX_RETRIES` 语义不变）。
- `setMetaExecutor(fn)` 与 `setSyncExecutor` / `setDeleteExecutor` 并列。
- **持久化向后兼容**：旧格式 `{type, boardId, attempts}` 在 `hydrateQueue` 中归一为 `ops = [type]`；新格式原样载入。不改 `queueKey` 存储键。
- 现有测试 `tests/a5-sync-queue.test.ts`、`tests/sync-queue-persist.test.ts` 必须扩覆盖：同板 meta+upload 共存、delete 压制、旧格式续跑、退避与错误派发不回归。

### 5.3 storage.ts

- `updateBoardMetaLocally(id, patch)`：调 `board-store.updateMetaLocal` + `enqueueMeta(id)`；不写画布 blob、不触发 `enqueue`（避免全量上传）。
- 注册 meta executor：PATCH `/api/canvases/:id/meta`（只发本地有值的字段），`credentials:'include'`。
  - 200 → `confirmServerMeta(id, body.canvas)`，并 `persistServerUpdatedAt(id, body.canvas.updatedAt)`。
  - 404（他端已软删）→ `reconcileRemoteDeletion(id)` + 派发 `deepdive:board-remote-deleted`，停止重试。
  - 401/403 → 派发 `deepdive:canvas-save-conflict`（带 code），停止重试并回滚本地改动（重新以服务端快照覆盖该板 meta）。
  - 网络失败 → `fail`，交队列退避。
- `fetchBoardListFromServer` 映射时带上 `isFavorite/isArchived/folderId`。

### 5.4 folder-store（Phase 2）

新增 `src/lib/folder-store.ts`，仿 `board-store` 的 `useSyncExternalStore` 稳定快照：

- 状态：`serverFolders`（`/api/folders` 快照）+ 本地缓存（scope 持久化，离线可见）。
- **在线优先**：新建/改名/删除立即请求；失败/离线时禁用入口并 toast（`离线中，暂不支持管理分组`），不做乐观回滚队列。
- 画板移动分组走 `meta` 队列，离线仍可用；若目标分组在服务端尚不存在（不可能，因为分组 CRUD 需在线），PATCH 400 → 派发冲突事件。
- `useFolders()` hook 加入 `src/hooks/useBoards.ts`。

### 5.5 UI

- 新增 `src/components/ui/BoardLibraryModal.tsx`（参照 `MySharesModal` 的弹窗模式，避免新增路由）：
  - 顶部搜索框（按画板名，前端过滤）、排序（最近更新 / 名称）、筛选 chip（全部 / 收藏 / 归档）。
  - Phase 2 左侧分组栏：全部 / 未分组 / 各分组 + 新建分组。
  - 画板行操作：打开、重命名、收藏、归档、移动分组（Phase 2）、删除（复用 App.tsx 现有 `handleDeleteBoard`）。
- `Topbar.tsx`：下拉顶部保持「收藏置顶 + 最近 5 块」快捷切换，底部新增「画板库」入口；Phase 2 按分组渲染小标题。删除/新建逻辑沿用现有回调。
- `App.tsx` 新增 `handleToggleFavorite` / `handleToggleArchive` / `handleMoveBoard`（Phase 2 分组 CRUD），打开库页的 state；自动命名/防抖保存链路不变。
- 共享默认板 `default-board` / `default-canvas` **禁止**收藏/归档/分组（全局共享同一行，改动会影响所有用户）。

## 6. 同步与离线语义

| 操作 | 本地行为 | 离线行为 |
| :--- | :--- | :--- |
| 收藏 / 取消收藏 | 立即更新并置顶，入 `meta` 队列 | 保留，联网补 PATCH |
| 归档 / 恢复 | 立即从默认视图隐藏，入 `meta` 队列 | 保留，联网补 PATCH |
| 移动分组 | 立即改归属，入 `meta` 队列 | 保留，联网补 PATCH |
| 新建/改名/删除分组 | 在线立即请求（Phase 2） | 入口禁用 + toast，不做本地乐观 |
| 搜索 / 排序 / 筛选 | 纯内存，零请求 | 完全可用 |

归档**不释放**配额：`assertCanCreateBoard` 仍按未软删画板计数，画板库/顶栏用量口径不变（`server/services/quota.service.ts:65-80`）。

## 7. 权限与安全

- 沿用 H1 严格属主制：meta 端点非属主 403、admin 放行；分组端点只认分组属主，admin 不代为管理（分组是个人偏好，不属管理对象）。
- `folderId` 绑定校验在服务端（§4.1），前端校验仅作体验。
- 新增 `tests/l2-authz-matrix.test.ts`（复制 `tests/authz-matrix.template.ts`）：覆盖 meta 端点与 `/api/folders` 的「匿名 401 / 非属主 403 或 404 / admin / 幂等」。

- 文档同步：`docs/数据库建表脚本.sql`、`docs/技术架构文档.md`、`CODEBUDDY.md`（画布列表真相段）、`docs/技术债清单.md`（folders 启用、tags 状态）。

## 11. 风险

- **sync-queue 升级**（高）：一板一任务 → 一板多操作，直接触碰刚重构的离线链路。缓解：PR2 独立、先补测试锁行为、持久化格式向后兼容、保留 delete 压制不变式。
- **`updated_at` 触发器副作用**（中）：收藏会推进 `updated_at` 并改变最近排序。缓解：meta 端点回传新版本号、前端按「收藏优先后最近」排序并接受收藏置顶语义。
- **分组/标签语义重叠**（中）：产品口径需明确，否则用户困惑。缓解：文档定义「分组=导航、标签=检索」，UI 文案区分。
- **范围蔓延**（中）：离线分组 CRUD、嵌套、拖拽排序易被追加。缓解：非目标显式列出，后续单独 spec。
