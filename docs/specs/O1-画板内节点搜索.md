# Spec O1 — 画板内节点搜索

> 来源：里程碑二期第 5 条「全文检索前端入口」（后端 `GET /api/canvases/:id/search` 早已就绪，但 `src/` 内 0 处调用）
> 状态：已实施（2026-09-16）
> 关联：H1 属主制（`searchNodes` userId 必填，ADR-0016）、#0090（suggested 不占额度口径）、#0095（ILIKE 无索引，Open）、技术债 #0002（tsvector 中文分词，独立路径）

## 1. 问题与现状

- 后端检索端点已存在：`canvases.ts` `GET /:id/search` → `searchUserNodes` → `searchNodes`（PG ILIKE + 内存 `includes()` 双模），严格属主制。
- 前端无任何入口；顶栏三区均已饱和（左区 9 项、右区 3 项、两外侧区 `shrink-0`），放不下常驻输入框。
- 既有实现有一批仅靠 `.length` 断言测不出的缺陷：无 `ORDER BY`、空 q 双模语义分叉（生产返 `[]`、dev 返 30 条）、不过滤 suggested、PG/内存响应形状不一致（snake_case vs camelCase、`created_at` 仅 PG 有、title 来源不一致）、`%`/`_` 未转义（PG 当通配符，内存按字面量）。

## 2. 目标与非目标

**目标**

1. 顶栏中区药丸新增**放大镜图标 + 下拉浮层**：输入关键词 → 检索**当前画板**节点 → 点击结果镜头飞至并临时高亮。
2. 打磨后端：空 q 早退、双模形状统一（camelCase 九键）、suggested 过滤、`%`/`_` 字面量化、`ORDER BY depth → pos_y → pos_x → id`、独立限流器。
3. 不标脏：高亮与选中态变更不得触发画板上传。

**非目标**

- 不做跨画板检索（仓储的 `canvasId` 可选能力保留但不暴露入口，`#0095` 记录复开条件）。
- 不加 `pg_trgm` 索引（见 #0095）；不做 tsvector 分词优化（见 #0002）。
- 不加键盘全局快捷键（Tooltip 上 `Alt+N/M/L/Space` 本就是无实现的装饰提示，本次不新增同类承诺）。
- 不在后端截断摘录文本（PG `LEFT()` 按字符、JS `slice()` 按 UTF-16 码元，emoji 上会分叉；截断交给 CSS `line-clamp-2`）。

## 3. 设计

### 3.1 后端：`searchNodes` 双模对齐（`server/repositories/canvas.repository.ts`）

- **空 q 早退**在 `getDb()` 之前：`const needle = queryText.trim(); if (!needle) return [];`——同时消灭「配了库走 PG、没配库落内存」的环境分叉。
- **响应形状统一 camelCase 九键**：`{id, canvasId, title, question, answer, noteContent, depth, model, type}`。PG 用带双引号别名（否则 PG 折成小写）；**不返回 `created_at`**（内存节点无此字段）。
- **title 与写入侧同规则**：PG `COALESCE(NULLIF(n.title,''), n.question)`，内存 `d.title || d.question || (便签|思考节点)`——对齐 `buildNodeRow` 的落库规则（此前 PG `n.question as title` 丢弃了真实 title 列）。
- **suggested 过滤**：PG `n.status <> 'suggested'`（列 NOT NULL，同 `countCanvasNodes`）；内存按 `d.status || (answer ? 'idle' : 'suggested')` 读 `data.status`（status 在内存节点位于 data，不是顶层）。与「灵感」开关仅视图级隐藏的口径一致——搜出被隐藏的占位会让用户「点进去什么都没有」。
- **匹配列**：PG `title/question/answer/note`；内存同四源，其中 note = `d.content || d.noteContent || d.note`（写入侧 `noteText = content || noteContent || note` 存进 note 列，`content` 列是它的前缀子集，故无需再搜 content）。
- **转义**：`%${q.replace(/[\\%_]/g, '\\$&')}%` + `ESCAPE '\'`，PG 退化为字面量子串，与内存 `includes()` 一致。
- **排序**：`ORDER BY n.depth ASC, n.pos_y ASC, n.pos_x ASC, n.id ASC`；内存收集后显式同序 `sort` 再 `slice(0,30)`（Map 插入序与 PG 不等价）。`depth` 是双模都可得的「离根最近」相关性代理；**不用 `created_at`**（内存侧不存在，等于再造分叉）。

### 3.2 路由与限流

- `SearchQuerySchema = z.object({ q: z.string().trim().max(100).default('') })`，经通用 `validate(schema, req.query)` 校验；**不设 `min(1)`**——空 q 语义是空结果，前端清空输入不应得 400。
- 新增独立 `canvasSearchRateLimiter`（`middleware/auth.ts`）：60s / 60 次 / `user_${id}` 回落 IP。300ms 防抖下一个多字词约 10 次请求，60 留余量；独立实例不共桶（#0089 教训）。

### 3.3 前端

- **命令 ref 桥**（既有模式）：`App.tsx` 声明 `triggerFocusNodeRef` → 传 `<DeepDiveCanvas>` → `onSearchResultClick` 传 `<Topbar>`。
- **浮层**（Topbar 中区，分隔线后）：`showSearchMenu` state 并入既有「点击空白 + Escape」useEffect；输入 300ms 防抖 + `AbortController`；trim 空**不发请求**；结果项 = 类型徽章（主题/便签）+ 标题 + `line-clamp-2` 摘录；输入框内 ↑/↓/Enter 导航并 `preventDefault`（React Flow 的 `isInputDOMNode` 守卫保证焦点在 INPUT 时删除键不触发）。
- **高亮用临时 `className`，不用 `selected`，绝不用 data 标记**：
  - `nodeHash` 白名单 = `{id,type,x,y,data}`（`board-ops.ts`）**不含 `className`** → 不改哈希、不标脏、零上传；
  - `selected` 会被 React Flow 识别为选中——浮层关闭后焦点离开搜索框，误按 Backspace/Delete 会**静默删掉刚选中的节点**（`deleteKeyCode=['Backspace','Delete']`）；
  - 未知 data 键被 `normalizeData` 折进 `custom` 并参与哈希 → data 标记直接标脏。
- **时序**：`nodesRef`+`setNodes` 同步写入 className → 2.5s 定时清除（2 × 1.2s keyframes 脉冲，`src/index.css` 新增 `node-search-hit`）→ 60ms 后 `setCenter(x+220, y+180, {zoom:0.9, duration:600})`（沿用分支新节点的镜头时序先例）。虚拟化（`onlyRenderVisibleElements`）无需特殊处理：store 先更新，节点进视口挂载时即带上 className。卸载时清理定时器。
- 命中节点已被他端删除时静默返回。

## 6. 风险

- **双模语义漂移**（中）：`repository-dual-mode.test.mjs` 只判函数体含 `getDb(` + `inMemoryStore.`，抓不到语义漂移；已用「键集合 + 转义 + 排序」三组用例钉死，改任一分支漏改另一边会红。
- **顶栏宽度**（低）：图标净增约 30px，与中区既有 6 项同一响应式退化体系，窄屏无需额外处理。
- **中文检索质量**（低）：ILIKE 子串匹配对中文可用但无分词/相关度；语义化检索见 #0002 与二期规划。
