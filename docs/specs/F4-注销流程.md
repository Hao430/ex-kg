# Spec F4 — 注销流程（软删除 + 30 天冷却恢复）

> 来源：`docs/里程碑与分期规划.md` F 组 F4（「字段与索引已存在，逻辑缺失」）；F2 验收「注销后按策略软删除，30 天内可恢复」
> 状态：本轮实施

## 1. 设计

**用户自助注销**：
- `DELETE /api/auth/account`（authMiddleware）：`deleted_at=NOW()` + `is_active=false` + **删除全部会话（踢下线）** + 审计 `account_deletion` → 200
- 注销后：`findUserByEmail/findUserById/findSession` 全部排除 `deleted_at IS NOT NULL` → 登录返回 401（账号不存在语义）；同邮箱可重新注册（users 邮箱唯一索引为 partial `WHERE deleted_at IS NULL`）
- 双模（PG UPDATE / 内存 Map 置 deleted_at 后从 users Map 语义排除——内存用 `deletedAt` 字段过滤）

**Admin 恢复（30 天冷却）**：
- `PUT /api/admin/users/:id/restore`：清 `deleted_at` + `is_active=true` + 审计 `account_restore` → 200；未注销/不存在 → 404
- `GET /api/admin/users` 列表默认排除已注销（新增 `includeDeleted` 参数不需要，保持排除）

**过期清除**：`server/jobs/log-cleanup.ts` 增加 `cleanupDeletedUsers(30)`——`deleted_at` 超过 30 天的用户**硬删除**（外键级联清数据，符合 GDPR 冷却期）；retention 0 全清（测试用）。

**user.repository**：`cleanupDeletedUsers(retentionDays)` 新增（双模）。

## 2. 测试先行（`tests/f4-account-deletion.test.ts`）

1. 注册新账号 → DELETE /api/auth/account → 200；旧 cookie /me → 401
2. 注销后 sign-in（旧密码正确）→ 401
3. 同邮箱重新注册 → 201
4. Admin restore 已注销账号（用注销前记录的 userId）→ 200；该账号可重新登录（新注册的账号存在同邮箱冲突场景——restore 用例改用独立账号验证）
5. 30 天过期：cleanupDeletedUsers(0) → 已注销用户被硬删；restore 硬删后 → 404
6. 非管理员调 restore → 403
