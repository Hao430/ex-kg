# Spec A4 — 画布保存乐观锁冲突检测

> 来源：`docs/里程碑与分期规划.md` A 组 A4 工作项；验收标准「同一画布双标签页并发编辑，后保存方收到冲突提示，不静默覆盖」
> 状态：本轮实施（后端 + 前端保存链路）

## 1. 设计

- 保存请求体新增可选字段 `expectedUpdatedAt`（ISO 时间串）= 保存方最后已知的服务端版本
- 服务端 `saveCanvas`：画布已存在且请求携带 `expectedUpdatedAt` 时，与服务端当前 `updated_at` 比对：
  - 一致（或画布不存在/未携带字段）→ 正常保存，未携带视为旧客户端兼容路径
  - 不一致 → **409** `{ error, code: 'CANVAS_SAVE_CONFLICT', latest_updated_at }`，拒绝覆盖
- 保存成功响应已含 `canvas.updatedAt`，前端将其记为下一次保存的 `expectedUpdatedAt`

## 2. 改动清单

- `server/repositories/canvas.repository.ts`：`saveCanvas` data 增加可选 `expectedUpdatedAt`；PG 与内存分支各自比对，冲突抛 `ConflictError('CANVAS_SAVE_CONFLICT')` 并携带 `latest_updated_at`
- `server/routes/canvases.ts`：透传 `expectedUpdatedAt`
- `src/lib/storage.ts`：`StoredBoard` 增加 `serverUpdatedAt?`；`syncBoardToBackend` 发送该字段、成功后写回响应的 `canvas.updatedAt`、409 时派发 `deepdive:canvas-save-conflict` 事件并返回冲突详情
- `src/App.tsx`：监听冲突事件 → `showToast('画板已在其他窗口被修改…')`

## 3. 测试先行（`tests/a4-optimistic-lock.test.ts`）

1. 首次保存（新建，无 expectedUpdatedAt）→ 200，响应含 updatedAt
2. 携带**正确** expectedUpdatedAt 保存 → 200
3. 携带**过期** expectedUpdatedAt 保存 → 409 + CANVAS_SAVE_CONFLICT + latest_updated_at
4. 画布不存在时携带任意 expectedUpdatedAt → 200（新建）
5. 不携带 expectedUpdatedAt → 200（兼容旧客户端）
