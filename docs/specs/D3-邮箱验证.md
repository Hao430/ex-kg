# Spec D3 — 邮箱验证（Nodemailer + 验证状态 + 未验证禁推理）

> 来源：`docs/里程碑与分期规划.md` D 组 D3、验收「未验证邮箱的账号发起推理被拒」；方案已确认：Nodemailer（发信）+ Mailpit（开发收信）+ 验证状态自研
> 状态：本轮实施

## 1. 设计

**数据模型**：users 新增（迁移 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）：
- `email_verified BOOLEAN DEFAULT FALSE NOT NULL`
- `verify_token VARCHAR(64)`、`verify_expires_at TIMESTAMPTZ`（24 小时有效）

**发信 `server/lib/mailer.ts`**：
- 环境变量 `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS` 齐备 → SMTP transport；否则 **jsonTransport 干跑模式**（邮件进内存 outbox 并 console.log 链接，开发/测试用；Mailpit 由 SMTP_HOST 指向 `localhost:1025` 即接入）
- `sendVerificationEmail(email, verifyUrl)`；测试辅助 `getOutboxForTest()/clearOutboxForTest()`

**流程**：
- 注册成功 → 生成 24h token → 存库 → 发验证邮件（链接 `${APP_URL||请求 origin}/verify-email?token=...`）
- `GET /api/auth/verify-email?token=`：校验 token 与有效期 → `email_verified=true` 并清空 token → 200；无效/过期 → 400 `INVALID_TOKEN`
- `POST /api/auth/resend-verification`（authMiddleware）：未验证才可重发（新 token 覆盖），已验证 → 400
- **强制点**：`chatQuotaMiddleware`——`email_verified === false` → 403 `EMAIL_NOT_VERIFIED`（admin 豁免；VIP 同受限于注册验证）；种子账号 `email_verified=true`（存量豁免）
- `.env.example` 补 SMTP_* 与 APP_URL

## 2. 测试先行（`tests/d3-email-verification.test.ts`）

1. 注册 → me `email_verified=false`；chat → 403 EMAIL_NOT_VERIFIED
2. 注册触发验证邮件（outbox 含 token）；GET verify-email?token → 200；me `email_verified=true`；chat 不再 403 EMAIL_NOT_VERIFIED
3. 无效 token → 400 INVALID_TOKEN
4. resend-verification → outbox +1；已验证账号 resend → 400
5. 种子账号 email_verified=true，chat 无 EMAIL_NOT_VERIFIED
