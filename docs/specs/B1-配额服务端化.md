# Spec B1+B2 — 配额服务端化 + VIP 过期锁定态

> 来源：`docs/里程碑与分期规划.md` B 组 B1/B2、决策 #4/#5/#6；验收标准 B 组前 4 条
> 状态：本轮实施

## 1. 权益模型（决策 #5/#6）

| 能力 | 体验版 (trial) | VIP 有效 | Admin | VIP 已过期 |
| :--- | :--- | :--- | :--- | :--- |
| 画板数量 | ≤3 | 无限 | 无限 | **禁新建** |
| 每画板 AI 节点（chat 类型） | ≤10 | 无限 | 无限 | **禁推理** |
| 读取画布 / 编辑便签保存 / 导出 | ✅ | ✅ | ✅ | ✅ |

有效身份判定：`role==='vip' && (vip_expires_at 为空或 > now)` → VIP 有效；`role==='vip' && vip_expires_at <= now` → **VIP 已过期**（区别于体验版，错误码不同）；`role==='user'` → 体验版；`role==='admin'` → 不受限。

## 2. 服务端强制点

| 校验 | 位置 | 触发条件 | 响应 |
| :--- | :--- | :--- | :--- |
| 画板数上限 | `canvas.service.saveUserCanvas`：画布不存在（即新建）时 | 体验版/过期 VIP 画板数 ≥3 | 403 `BOARD_LIMIT_REACHED` |
| 节点数上限 | chat 路由 `chatQuotaMiddleware`（替换旧点数 quotaMiddleware） | 体验版/过期 VIP 目标画布 chat 节点 ≥10 | 403 `NODE_LIMIT_REACHED` |
| VIP 过期禁推理 | 同上中间件，最先校验 | 过期 VIP 发起推理 | 403 `VIP_EXPIRED` |
| VIP 过期禁建画板 | 新建画板校验同处 | 过期 VIP 新建 | 403 `VIP_EXPIRED` |

- `canvas.repository` 新增 `canvasExists(id)`、`countCanvasNodes(canvasId)`（双模）
- `/api/auth/me` 响应新增 `entitlements: { plan: 'trial'|'vip'|'admin', vipExpired: boolean, boardLimit, nodeLimit }`（B4 前端渲染依据）

## 3. 前端最小适配

- `syncBoardToBackend`：403 视为**永久失败不重试**，派发 `deepdive:canvas-save-conflict` 同类事件展示服务端错误文案（避免配额 403 被重试队列打 5 次）

## 4. 测试先行（`tests/b1-quota.test.ts`）

1. 体验版建第 4 个画板 → 403 BOARD_LIMIT_REACHED（直连 API）
2. VIP 建第 4+ 个画板 → 200（不受限）
3. 体验版画板 10 个 chat 节点后发起推理 → 403 NODE_LIMIT_REACHED（无 GEMINI_API_KEY 时断言在扣费/推演前返回）
4. 过期 VIP 推理 → 403 VIP_EXPIRED；过期 VIP 新建画板 → 403 VIP_EXPIRED
5. 过期 VIP 读取画布 / 保存编辑 → 200
6. Admin 建第 4+ 画板 → 200
7. me 返回 entitlements（trial / vipExpired 两种）
