# Spec A3 — nodes + edges 批量保存事务化

> 来源：`docs/里程碑与分期规划.md` A 组 A3 工作项
> 状态：本轮实施

## 1. 现状与问题

`server/repositories/canvas.repository.ts` 的 `saveCanvas` PG 分支在事务内**逐条** INSERT nodes（每节点一次 query，21 参数）与 edges（每边一次 query，9 参数）。300 节点画布一次保存 = 700+ 次往返，事务持锁时间长、保存延迟高。

## 2. 目标

- nodes / edges 改为**多值批量 INSERT**（单条 SQL 携带多行 VALUES），在既有事务内执行
- 分块（chunk）策略：nodes 每批 ≤200 行（200×21=4200 参数，远低于 PG 65535 上限）；edges 每批 ≤500 行
- 空数组跳过对应批量 INSERT（含 DELETE 后无数据场景）
- 行为完全不变：全量替换语义（先 DELETE 再 INSERT）、失败整体 ROLLBACK、字段映射不变

## 3. 测试先行（`tests/a3-batch-save.test.ts`）

1. 保存 300 节点 + 500 边 → 200，GET 回读节点/边数量完整
2. 覆盖保存：同一画布再次保存不同数据集 → 替换而非追加
3. 保存空 nodes/edges → 200 且原数据清空
4. 特殊字符（单引号/emoji/反斜杠）节点往返无损（防批量拼接 SQL 破坏转义）
5. 富字段往返：messages JSONB、grounding、custom_data、parentId
