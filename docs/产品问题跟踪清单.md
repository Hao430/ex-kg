## B. 增长与传播

### B1 公开分享提前 `已落地（K2 + K6，2026-09-08，含注册自动克隆钩子）` `P0`

**问题**：画布是天然可视化传播物料，公开分享却排到二期，且无论证；产品无法被传播。

**方案**（评审结论：A+B 一起做，约 3-5 人日）：
- ⭐ **只读快照分享页**【成本：低】：`POST /api/canvas/:id/share` 生成 `share_id`（nanoid），写入已建的 `canvas_shares`（存画布全量 JSON 快照 + 版本），路由 `/share/:shareId` 走 `main.tsx` 分流（同 `/verify-email` 模式），复用画布组件关闭编辑交互。快照式不做实时同步，天然规避权限边界。属主可「停止分享」= 软删该行。
- ⭐ **分享页传播钩子**【成本：低】【依赖：上一条】：底部固定「由 枝想 生成」+ CTA「用 AI 深挖这个主题」；访客注册后**自动克隆该画布进其账号**（服务端 clone 机制，可与 D1 示例画布复用）——看到别人的思考树 → 一键拥有可编辑副本，最直接的转化闭环。
- SEO 长尾（缓做）【成本：中】：分享页预渲染标题取根节点主题，学者分享的研究推演天然是长尾内容。需 `APP_URL` 公网可达。

**验收**：分享链接可打开只读画布（移动端见 F1）；注册后画布自动克隆成功；停止分享后链接 404。

**克隆钩子落地（Spec K6，2026-09-08）**：评审原「服务端 clone 机制」改为**客户端克隆**——CTA 点击记录意图（localStorage，7 天过期、读后即焚）→ 登录/注册成功且画板就绪时拉公开快照 → `saveBoard()` 走既有同步队列落服务端，配额由 save 路径 `assertCanCreateBoard` 硬拦截 + 客户端预检双保险，不新增端点/限流器面。同码只克隆一次（`deepdive_cloned_codes`）；克隆后直接切入新画板并 toast；`generating` 遗留态归一化防永久转圈；上报 `share_clone` 事件（无 PII）。

### B2 图片导出 `已落地（K1，2026-09-07）` `P0`

**问题**：导出仅 JSON / Markdown，无 PNG/图片——视觉化产品无法被转发到任何地方。

**方案**：
- ⭐ **前端 React Flow 内置导出**【成本：低（1-2 人日）】：`@xyflow/react` v12 自带 `useReactFlow().toImage()`（png/jpeg/svg）。两个必做细节：a) 导出前临时切亮色主题并内联字体（KaTeX 公式与自定义字体嵌入是主要坑）；b) 图片角落加品牌水印。
- 备选：服务端 Puppeteer 渲染【成本：中高】——仅当前端方案字体/公式渲染质量不达标时升级；小团队不值得为此加运维面。
- 不建议：自研 canvas 重绘——节点含 Markdown/KaTeX 富文本，重绘成本极高。

**验收**：任意画布一键导出 PNG，公式渲染正确，含水印。

### B3 全站零埋点 `已落地（K4，2026-09-08）` `P0`

**问题**：无激活率、画布深度分布、节点数中位数、撞配额流失等任何数据，产品决策全在盲飞。

**方案**：
- ⭐ **Umami 自托管**【成本：低】：MIT 开源、单 Docker 容器、约 2KB 脚本、中文界面、国内访问无障碍；可与主库同 PG 实例。备选 Plausible（资源略高）、PostHog（二期需要漏斗/回放再上）。前端 `<script async>` 一行接入，侵入近零。
- 备选：自写极简埋点表（`POST /api/track` 单表）——可控但无现成看板，仅当不想加容器时选。

**首期 10 个关键事件**：① landing 浏览 ② 注册发码 ③ 注册成功 ④ 首次登录 ⑤ 画布创建 ⑥ AI 节点首次生成（激活关键动作）⑦ 每日活跃 ⑧ 导出点击 ⑨ 分享链接点击（B1 上线后）⑩ 节点数达 10（配额墙触达 = 付费意愿信号）。

**落地（Spec K4）**：`docker-compose.umami.yml`（独立 3001 端口 + 专用 PG）+ `src/lib/analytics.ts`（VITE_UMAMI_SRC/WEBSITE_ID 双变量开关，未配置全 no-op）；10 事件已接线（⑨ 落为 `share_view` 分享页浏览成功，⑩ 落为 `quota_wall` 配额拦截上报）；隐私红线：事件 data 仅枚举/计数零 PII。**待部署 Umami 实例并在 .env 配置后于看板验收。**

**验收**：Umami 看板可见上述 10 事件；注册→首次生成漏斗可读。

## D. 激活与引导

### D1 冷启动引导单薄 `已落地（K5，2026-09-08）` `P1`

**问题**：空白画布 + 一个待填根节点；四类人群场景无对应模板画布，从「能干嘛」到「第一个分支」全靠用户自悟。

**方案**（评审结论：A 为主 + C 叠加，B 二期再上）：
- ⭐ **内置示例画布**【成本：中低】：首次登录注入 3 个只读示例（覆盖学者/架构师/自学者三类人，如「网络效应如何形成」「论文选题怎么拆解」「系统架构权衡」），直接展示划词分支→推演→来源角标全链路。价值最高，所见即所得。【依赖：内容策划 + seed 机制】
- **空态 checklist**【成本：低】：4 步清单（建画板→划词→生成→导出）纯前端浮层，完成后消失。与示例画布叠加。
- AI 引导式开场（缓做）【成本：中】：根节点改为引导选项，选中后自动生成首个 AI 分支制造「啊哈时刻」。**需先解决 D2 配额计数**（引导节点须不计入 10 节点上限），二期再上。

**验收**：新账号首屏可见示例画布；示例内容经内容评审（推荐课题为可深挖的学习型议题，符合文案规范）。

**落地（Spec K5）**：示例画布改为纯前端静态只读（`src/lib/sample-boards.ts` 三块：学者/架构师/自学者），复用 K2 只读节点渲染，模态查看器双入口（落地页场景卡 + Topbar 画板下拉）；**评审原「首次登录注入」方案因 3 示例占满免费版画板配额被否决**。空态 checklist 4 步（建画板/划词分支/AI 生成/导出）已接线动作发生处，全完成自动消失。

### D2 配额双层语义错位 `已落地（J2，2026-09-07）` `P0`

**问题**：后端按**含 suggested 占位节点**计数、前端预检**排除** suggested——用户看到「还能提问」却被 403，客诉制造机。

**方案**（评审结论：B，单一事实源原则）：
- ⭐ **配额余量 API**【成本：低-中】：chat 响应或独立 `/api/quota` 返回 `{used, limit, remaining}`；前端删掉本地计数预检只做展示，后端保持唯一裁判。后端 quota middleware 已有计数逻辑，透出即可。【依赖：前端 `storage.ts` 小改】
- 短期止血：前端提示语改「以实际可用为准」。
- 否决项：后端对齐前端（排除 suggested）需改计数逻辑并回归全部配额测试，且 suggested 占位本是诱导升级抓手，防线后移；前端对齐后端则「空画板就剩 6 次」，体验倒退。

**验收**：前端展示余量与后端拦截完全一致；体验版在剩余 0 次前不会收到意外 403。

### D3 撞配额后的升级引导 `已落地（K7，2026-09-08）` `P2`

**问题**：NODE_LIMIT_REACHED 错误框带升级按钮，但升级价值感知依赖 Admin 是否配置了 vip-only 模型。

**方案**：升级弹窗改为展示真实权益对比（画板数/节点数/模型），vip-only 模型未配置时隐藏模型行、不展示空气权益。【成本：低】【依赖：`/api/auth/me` entitlements 已有数据】

**落地（Spec K7）**：弹窗打开时拉 `/api/quota` 展示真实用量（画板 X/3、当前画板节点 Y/10，配额墙触发点透传 canvasId）；免费版权益数值取服务端 limit（失败回退常量）；`/api/quota` 新增 `vipOnlyModelCount`（只透出数量不透出模型名），未配置时隐藏「专享模型」行；删除「常规响应队列」空气权益行。

## E. 工程与交付风险

### E1 PG 路径零测试覆盖 `已落地（J3，真库待跑）` `P0`（上线前必做）

**问题**：测试套件仅跑 memory 降级分支；H、I 两组「上线前连真库冒烟」至今未勾选。

**方案**（评审结论：A 起步，稳定后升 C；testcontainers 暂不引入）：
- ⭐ **docker-compose 起 postgres:16 + PG 冒烟测试**【成本：低】：`tests/pg/*.pg.test.ts`（环境变量 `PG_SMOKE=1` 才加载，不破坏现有 `npm test` 语义），复用现有 `createApp` 骨架，优先覆盖 `canvas.repository` 的软删/越权/`ON CONFLICT ... WHERE deleted_at IS NULL` 防复活与双模归一化对齐。
- CI 矩阵（后续）【成本：中】：memory / PG 两个 job，PG job 先 `docker compose up postgres` 再跑全套件。

**验收**：H/I 两组的「上线前连真库冒烟」两项在里程碑文档勾选。

### E2 PG 故障静默降级内存假成功 `已落地（J1，2026-09-07）` `P0`

**问题**：DB 失败时写入内存「假成功」，重启即丢——与「生产级」宣称存在数据存活性敞口。

**方案**（评审结论：A + B 组合，否决 C）：
- ⭐ **生产 fail-fast**【成本：低】：`NODE_ENV=production` 且配置了 `DATABASE_URL` 时，PG 不可用直接 503（新错误码 `DB_UNAVAILABLE`），禁落内存；开发/测试环境降级不变。「配了库就必须用库」。
- ⭐ **健康检查强化**【成本：低】：`/api/db/status` 增加 `degraded` 字段，部署层对 degraded 持续 >60s 告警或重启。
- 否决项：写路径熔断/只读降级——需重写降级判定与数据回流，双写分叉风险大，不值得。

**验收**：生产模拟 PG 宕机，写请求 503 而非 200；`/api/db/status` 如实反映 degraded。

### E3 收官后连打安全补丁的流程隐患 `已落地（J4，2026-09-07）` `P1`

**问题**：一期收官后 H 组 4 处（含水平越权）+ I 组 8 处（含配额绕过），验收靠专项排查兜底。

**方案**（评审结论：A + C 立即做，B 下次新增端点时落地）：
- ⭐ **上线前安全 checklist 固化到 `docs/`**【成本：低】：越权三角（读/写/删 × 属主/他人/admin/匿名）、软删复活、注入、限流绕过；每项标注对应测试文件。**把 H/I 两批缺陷逐条反推成条目，防止同一模式三犯。**
- ⭐ **发布门禁**【成本：低】：里程碑设 hard gate——安全 checklist 勾完 + `tsc --noEmit` + 全测试绿 + PG 冒烟，四项未全勾不得标记里程碑完成。
- 越权矩阵测试模板（随下一批端点）【成本：中】：`tests/` 表驱动「资源 × 角色 × 动作」模板，新端点照抄填空。【依赖：tests 目录只读豁免一次】

**验收**：checklist 文档落库；下一次里程碑收官时四项门禁全绿。

### E4 模型配置单点依赖 `已落地（K8，2026-09-08）` `P2`

**问题**：管理员未选模型时全站 chat 返回 400 MODEL_NOT_CONFIGURED，新装忘配置即全站不可用。

**方案**：
- Admin 后台配置页加显式告警横幅（模型未配置 = 全站推理不可用）；`/api/db/status` 或 admin overview 暴露 `model_configured` 布尔。【成本：低】
- 部署文档 bootstrap 步骤补「首次启动必须配置模型」。
- 不建议：自动回落默认模型——与「`getSavedAiModelConfig()` 不合并默认值」的既有口径冲突，测试锁定，改动收益低。

**验收**：新环境未配置模型时 Admin 首页可见醒目告警。

**落地（Spec K8）**：`/api/admin/overview` 暴露 `modelConfigured`（判定抽为 `isModelConfigured()` 与 chat 拦截同口径单一来源）；Admin 总览页/模型配置页顶部红色告警横幅 + 一键跳转配置，保存后自动消失；README 补 bootstrap 步骤；未做默认模型回落（遵守既有口径）。

**问题**：目标用户（学者/备考/终身学习者）是移动阅读浓度最高人群，移动端进「明确不做」且无论证。

**方案**（评审结论：A，只做分享页只读最小适配）：

**验收**：微信内打开分享链接可完整浏览画布；主应用在 <1024px 仍维持现有行为。

## 执行顺序建议

| 批次 | 内容 | 理由 |
| :--- | :--- | :--- |
| **第 0 批（立即）** | E2 生产 fail-fast、D2 配额余量 API | 一个守住数据底线，一个消除最高频用户困惑 |
| **第 1 批（上线门禁）** | E1 PG 冒烟、E3 checklist + 发布门禁 | 上线前必做，流程止血 |
| **第 2 批（传播）** | B2 图片导出 → B1 分享页 → F1 分享页移动适配 | B2 半天级先上；B1+F1 共用路由分流；让产品能被看见 |
| **第 3 批（度量）** | B3 Umami 埋点（10 事件） | 先有数据再评估后续投入 |
| **第 4 批（激活）** | D1 示例画布（复用 B1 克隆机制）+ 空态 checklist | 依赖第 2 批的 clone 能力 |
| **持续** | A1/A2 定位收敛、E4、D3 | 穿插进行，不阻塞主线 |

> 关键复用关系：B1 分享克隆 ↔ D1 示例画布 seed（同一 clone 机制）；B1 分享路由 ↔ F1 移动适配（同一分流点）；D2 余量 API ↔ D3 升级引导（同一 entitlements 数据）。
